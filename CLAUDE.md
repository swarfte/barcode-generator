## Project context

This repo is a **Vue 3 starter template** (package name `vue-base`). Despite the directory name `PCMS-importfile-generator`, the project has
been repurposed as a generic Vue 3 scaffold for building new projects on. Do not assume any PCMS, card, seal, or vault business logic — there is
none. Treat this as a blank template that users will extend.

## Commands

  ```bash
  pnpm install     # install dependencies
  pnpm dev         # start Vite dev server with HMR
  pnpm build       # type-check (vue-tsc) then vite build for production
  pnpm preview     # preview the production build locally

  There is no test runner, linter, or formatter configured. Type-checking happens via vue-tsc -b as part of pnpm build — run pnpm build to catch
  type errors. There is no separate typecheck script.

  Architecture

  This is a single-page Vue 3 app using <script setup lang="ts"> with Composition API. The stack and how each piece is wired up:

  Build & tooling — Vite 8 with three plugins in vite.config.ts:
  - @vitejs/plugin-vue — SFC compilation
  - vite-plugin-vue-devtools — in-browser devtools overlay
  - unplugin-auto-import + unplugin-vue-components both configured with ElementPlusResolver() — this is why Element Plus components (<el-button>,
  <el-card>, etc.) appear in templates without imports, and why ElMessage-style APIs are auto-resolved at runtime. Note: the TS resolver for
  auto-imports is imperfect; if vue-tsc reports a missing name for an Element Plus function (e.g. ElMessage), import it explicitly from
  'element-plus' rather than relying on auto-import. Generated declaration files: components.d.ts (component types), auto-imports.d.ts (API types)
   — these are regenerated by the plugins and should not be hand-edited.

  App bootstrap (src/main.ts) — mounts App.vue, registers Pinia (with pinia-plugin-persistedstate applied to the pinia instance), Element Plus
  (full lib + CSS import from 'element-plus/dist/index.css'), and the router. Order matters: pinia.use(piniaPluginPersistedstate) must run before
  app.use(pinia).

  Routing (src/router.ts) — createWebHistory router. Currently only the / route → HomeView. Add new routes here; App.vue is just <router-view>.

  State — Pinia stores can opt into localStorage persistence by setting persist: true in the store's options (the plugin is already registered
  globally).

  TypeScript config — tsconfig.json uses project references to tsconfig.app.json (app code) and tsconfig.node.json (Vite config). Strict linting
  flags are enabled in tsconfig.app.json: noUnusedLocals, noUnusedParameters, noFallthroughCasesInSwitch, erasableSyntaxOnly. The @/* path alias
  maps to src/*.

  Views — src/views/ holds route components. HomeView.vue is a landing page describing the template's stack; replace it with the actual project's
  content when extending.

  Conventions

  - Use <script setup lang="ts"> for all new SFCs.
  - Prefer the @/ alias over relative imports.
  - When adding Element Plus components in templates, do not import/register them — the resolver handles it. Only explicit imports are needed for
  imperative APIs like ElMessage, ElMessageBox, ElNotification when the type-checker complains.
  - src/style.css is the global stylesheet imported in main.ts; keep it minimal.
