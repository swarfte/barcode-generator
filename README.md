# Vue 3 Base Template

A ready-to-use Vue 3 starter scaffolded with Vite 8, pre-configured with the essentials — Vue Router, Pinia, Element Plus, VueUse, and more — so you can start building on day one.

> **Note:** Despite the directory name `PCMS-importfile-generator`, this repository currently serves as a generic Vue 3 base template (package name `vue-base`). There is no PCMS-specific business logic here; extend it as you see fit.

## Tech Stack

| Tool | Version | Purpose |
| --- | --- | --- |
| [Vite](https://vite.dev) | v8 | Build tool with instant cold start and fast HMR |
| [Vue 3](https://vuejs.org) | v3.5 | Progressive framework using `<script setup>` + Composition API |
| [Vue Router](https://router.vuejs.org) | v5 | Official router, configured with `createWebHistory` |
| [Pinia](https://pinia.vuejs.org) | v3 | Type-safe state management |
| [pinia-plugin-persistedstate](https://prazdevs.github.io/pinia-plugin-persistedstate) | v4 | Opt-in localStorage persistence for Pinia stores |
| [Element Plus](https://element-plus.org) | v2.14 | Vue 3 UI library, auto-imported via `unplugin` |
| [VueUse](https://vueuse.org) | v14 | Collection of essential Vue composition utilities |
| [Vue DevTools](https://devtools.vuejs.org) | v8 | Browser-independent inspector via `vite-plugin-vue-devtools` |
| [TypeScript](https://www.typescriptlang.org) | ~v6 | Strict type-checking through `vue-tsc` |

## Requirements

- Node.js (LTS recommended)
- [pnpm](https://pnpm.io) (the scripts below assume pnpm)

## Commands

```bash
pnpm install     # install dependencies
pnpm dev         # start the Vite dev server with HMR
pnpm build       # type-check (vue-tsc) then build for production
pnpm preview     # preview the production build locally
```

There is **no test runner, linter, or formatter** configured. Type-checking runs as part of `pnpm build` via `vue-tsc -b` — run `pnpm build` to catch type errors.

## What's Wired Up

- **Auto Import** — Element Plus components and APIs are auto-resolved by `unplugin-auto-import` + `unplugin-vue-components` (both configured with `ElementPlusResolver()`). Use `<el-button>`, `<el-card>`, etc. in templates without imports.
- **TypeScript Ready** — Strict TS config with `vue-tsc` for type-checking; `@/*` path alias maps to `src/*`.
- **Persistent State** — Pinia stores can opt into `localStorage` persistence by setting `persist: true` in the store's options (the plugin is registered globally in `main.ts`).
- **DevTools** — Browser-independent Vue DevTools overlay available in development.

## Conventions

- Use `<script setup lang="ts">` for all new SFCs.
- Prefer the `@/` alias over relative imports.
- Do **not** import/register Element Plus components in templates — the resolver handles it. The only exception is imperative APIs like `ElMessage`, `ElMessageBox`, or `ElNotification`: if `vue-tsc` reports a missing name, import them explicitly from `'element-plus'`.
- Keep `src/style.css` minimal — it's the global stylesheet imported in `main.ts`.

### Generated files (do not hand-edit)

- `components.d.ts` — component type declarations (regenerated by `unplugin-vue-components`)
- `auto-imports.d.ts` — auto-import API type declarations (regenerated by `unplugin-auto-import`)

### Bootstrap ordering

In `src/main.ts`, the persist plugin must register before Pinia mounts:

```ts
const pinia = createPinia()
pinia.use(piniaPluginPersistedstate)   // before app.use(pinia)
app.use(ElementPlus)
app.use(pinia)
```

## Extending

- **Add routes** in `src/router.ts`.
- **Add views** under `src/views/`.
- **Add Pinia stores** anywhere under `src/` and opt into persistence with `persist: true`.
- **Replace `HomeView.vue`** with your project's actual landing content.
